# HRTA WebApp — โหมดออนไลน์ (เกมเลขเพดาน 2–4 คน) · คู่มือฉบับสมบูรณ์

โหมดเดิมทั้งหมด (เล่นกับ AI / ส่งเครื่องกัน / เกมอื่น ๆ) ยังทำงานเหมือนเดิม โหมดออนไลน์เป็นปุ่มเพิ่มในหน้าตั้งค่าเกมเลขเพดาน

## 1) ภาพรวม
```
มือถือ 2–4 เครื่อง (GitHub Pages: index.html + online/*.js)
   │ HTTPS  → Edge Function `nn-api`  (เริ่มเกม / ลงไพ่ / ตรวจหมดเวลา / ยอมแพ้)   ← ผู้ตัดสิน รันกติกาและสุ่มไพ่
   │ WebSocket → Supabase Realtime   (ห้อง / สถานะเกม / มือของตัวเอง)
   ▼
Supabase: Auth (anonymous) · Postgres + RLS · Edge Function · Realtime
```
- เซิร์ฟเวอร์เป็นผู้ตัดสินทุกอย่าง client ส่งแค่ "ขอลงไพ่ใบนี้" ; สำรับ/กองทิ้งอ่านไม่ได้ ; มือคนอื่นอ่านไม่ได้ (RLS)
- engine เป็นไฟล์เดียวกับในเกมออฟไลน์ (`online/nn-engine.js` คัดลอกตรงจาก `index.html` และมีเทสต์เทียบทุกตา)
- โหมดเกม: **แพ้ 1 คน** (ที่เหลือชนะ) และ **คัดออก** (4→3→2 เหลือผู้ชนะ 1 คน; ตกรอบแล้วกองรีเซ็ตเป็น 0 และเมื่อเหลือ 2 คนใช้พลังไพ่แบบ 2 คน)
- เวลา: ตาละ 60 วินาที · หลุดการเชื่อมต่อรอได้ 120 วินาที · หมดเวลา/หลุดนาน/ออกจากเกม = ยอมแพ้ · Host หายเกิน 60 วินาที ย้ายให้คนอื่นอัตโนมัติ · ไม่มี AI แทนผู้เล่น
- ยังไม่มีเหรียญรางวัลในโหมดออนไลน์ (เหรียญของแอปเก็บใน localStorage แก้ได้จากเครื่อง จึงไม่ปลอดภัยพอ)

## 2) ติดตั้ง (ทำตามลำดับ)
**Supabase**
1. SQL Editor → รันไฟล์ใน `supabase/migrations/` **ตามลำดับ 001 → 002 → 003 → 004 → 005** (005 ต้องรัน **ก่อน** วางโค้ด Edge Function ใหม่ เพราะฟังก์ชันอ่านคอลัมน์ใหม่) (ทีละไฟล์ ต้องขึ้น Success)
2. Authentication → Sign In / Providers → เปิด **Allow anonymous sign-ins**
3. Edge Functions → สร้างฟังก์ชันชื่อ **`nn-api`** → วางทั้งไฟล์ `supabase/functions/nn-api/index.ts` → Deploy
   - ปิด "Verify JWT" ของฟังก์ชันนี้ (โค้ดตรวจ JWT ผู้เล่นเองแล้ว)
   - ไม่ต้องตั้ง secret: ระบบใส่ `SUPABASE_URL` และ service key ให้เอง (ห้ามนำไปใส่ GitHub) · ถ้าปิด legacy key แล้ว ให้เพิ่ม secret `SB_SECRET_KEY` · ถ้าเปิดจากโดเมนอื่นเพิ่ม `ALLOWED_ORIGINS`
**GitHub (repo `HRTA2026`, branch `main`)**
4. แตก ZIP แล้วอัปโหลดทับทุกไฟล์ (ต้องมีโฟลเดอร์ `img/`, `online/`, `supabase/`, `docs/`)
5. รอ Pages deploy แล้วเปิด `…/sw.js` ต้องเห็น `VERSION = "v31"` → ล้างแคช/เปิดแท็บใหม่
**ทุกครั้งที่อัปเดตโค้ด:** ถ้าแก้ไฟล์ใน `online/` ที่เกี่ยวกับเซิร์ฟเวอร์ (`nn-engine.js`, `nn-server.js`, `nn-api-core.js`) ให้รัน `node tools/build-edge.js` แล้ววาง `index.ts` ใหม่ใน Edge Function ด้วย ; เปลี่ยน `VERSION` ใน `sw.js` ทุกครั้งที่ deploy

## 4) ต้นทุนและข้อจำกัดของ Free tier (ตรวจหน้าทางการก่อน deploy จริง)
ตัวเลขจากบทความสรุปราคาภายนอก (ไม่ใช่หน้าทางการ ณ ต้น พ.ย. 2026): DB 500 MB · Edge Function 500,000 ครั้ง/เดือน · Realtime 200 connection พร้อมกัน, 2 ล้านข้อความ/เดือน · egress 5 GB · **โปรเจกต์ถูก pause เมื่อไม่มีการใช้งาน 7 วัน** (ข้อมูลไม่หาย แต่เกมใช้ไม่ได้จนกด Restore)
ประมาณการของเรา (ไม่ได้วัดจริง): 1 ตา = 1 invocation, เกมละ 40–60 ตา → รองรับราว 10,000 เกม/เดือน ; Realtime ราว 4,000 เกม/เดือน ; 200 connection ≈ 50 โต๊ะพร้อมกัน — พอสำหรับทีม/กลุ่มเพื่อน
ต้องจ่ายเมื่อไร: อยากให้พร้อมเล่นตลอดโดยไม่ถูก pause (Pro) หรือผู้ใช้เกินเพดานข้างต้น · ผู้ใช้ทั้งทีมใช้ Wi-Fi เดียวกันอาจชนขีดจำกัดการ sign-in แบบ anonymous ต่อ IP (ดู Authentication → Rate Limits)

## 10) สงครามไพ่ "ยุทธวิธี" ออนไลน์ 2 คน (v38)

ใช้ห้อง/ล็อบบี้/heartbeat/Rematch ชุดเดียวกับเกมเลขเพดาน ห้องแยกชนิดด้วยคอลัมน์ `rooms.game_type` (`nn` | `war`) · ไม่มี AI แทนผู้เล่น · ไม่มีเหรียญในโหมดออนไลน์ (เหตุผลความปลอดภัยเดิม) · ไม่มีพลังพิเศษของไพ่

### ติดตั้ง (ต่อจากขั้นตอนข้อ 2 — ทำหลังติดตั้งเกมเลขเพดานแล้ว)
1. **รัน migration `supabase/migrations/006_war_online.sql`** ใน SQL Editor (เลข 005 ถูกใช้โดย `005_new_card_powers.sql` แล้ว) — เพิ่มคอลัมน์ `rooms.game_type` (ค่าเริ่มต้น `nn` ห้องเดิมไม่เปลี่ยน), `rooms.war_cfg` และฟังก์ชัน `war_create_room`, `war_update_settings`, `war_commit_start`, `war_commit` (สองตัวหลังเรียกได้เฉพาะ `service_role`) และเพิ่มการตรวจชนิดห้องใน `nn_update_settings`
2. **สร้าง Edge Function ใหม่:** `node tools/build-edge.js` แล้วนำ `supabase/functions/nn-api/index.ts` ไปวางทับ (ชื่อฟังก์ชันเดิม `nn-api`) แล้ว Deploy — ไฟล์รวม engine เลขเพดาน + `war-engine/war-server/war-api-core` ไว้ด้วย (ไม่ต้องตั้งค่า secret เพิ่ม)
3. อัปโหลดไฟล์เว็บทั้งชุด (มี `online/online-war.js` ใหม่) — เปิดจากแท็บสงครามไพ่ → 🧠 ยุทธวิธี → "ออนไลน์ 2 คน" หรือจากปุ่มออนไลน์ในแท็บเกมเลขเพดาน แล้วเลือกเกมตอนสร้างห้อง

### กติกา/ข้อกำหนดฝั่งเซิร์ฟเวอร์
- เซิร์ฟเวอร์สุ่ม/จั่ว/ตัดสินเอง · การเลือกพร้อมกันแบบ **commit–reveal**: ไพ่ที่เลือกเก็บใน `game_secrets.pend` (client อ่านไม่ได้) public state เผยแค่ `cm = [ยืนยันแล้ว?, ยืนยันแล้ว?]` เมื่อทั้งคู่ยืนยันจึงเปิดไพ่+ตัดสินใน transaction เดียวแล้วเผยผลผ่าน `public_state.ev`
- การเลือกในสงคราม (ไพ่คว่ำ 3 + ใบตัดสิน / ถอย) ใช้กลไกเดียวกัน · คนที่ไพ่หมดมือกลางสงครามไม่ต้องเลือก (แพ้ศึกนั้นอัตโนมัติ)
- กันลงซ้ำ/ชน: `request_id` (ส่งซ้ำได้ปลอดภัย) + `expected_version` เหมือน `nn_commit_action`
- เวลา: **60 วินาทีต่อการเลือก** (ทั้งสองคนต้องเลือก) · ฝั่งที่ยังไม่เลือกเมื่อหมดเวลา = ยอมแพ้ · หลุดสัญญาณรอ 120 วินาที · ออกจากเกม = ยอมแพ้ · **ทั้งคู่ไม่เลือกเลย = จบแบบเสมอ (ไม่ลงโทษใคร)** — เป็นการตัดสินใจของผู้พัฒนา: ถ้าใครคนเดียวเลือกแล้วอีกฝั่งหายไป อีกฝั่งแพ้; ถ้าทั้งคู่หายไปไม่มีใครผิดฝ่ายเดียว
- ข้อมูลที่ client เห็น: มือตัวเอง (`player_private_states`, RLS), จำนวนไพ่ในมือ/กองจั่ว/กองรางวัล/ทิ้ง, ไพ่ที่เปิดแล้ว, จำนวนครั้งที่เพิ่มเดิมพัน — ไม่เห็นมือ/ลำดับกองจั่ว/ไพ่คว่ำของอีกฝั่ง

### ⚠️ สิ่งที่ยังไม่ได้ทดสอบ (ต้องทดสอบด้วยเครื่องจริงก่อนใช้งานจริง)
SQL (`006_war_online.sql`) และ Edge Function ที่ build ใหม่ **ยังไม่เคยรันกับ Supabase จริง** — เทสต์ทั้งหมดใช้ฐานข้อมูลจำลองที่เลียนพฤติกรรมของฟังก์ชัน SQL ขั้นตอนทดสอบด้วยเครื่องจริง:
1. รัน migration 006 ไม่มี error · `select game_type from rooms limit 1` ได้ `nn` กับห้องเก่า
2. Deploy `nn-api` ใหม่ → สร้างห้องเลขเพดานเก่า เล่นจบหนึ่งเกมเพื่อยืนยันว่าไม่พัง
3. มือถือ 2 เครื่อง (หรือ 1 เครื่อง + แท็บไม่ระบุตัวตน): A สร้างห้อง "สงครามไพ่" ตั้งชนกัน/คนโง่ → B เข้ารหัส → ทั้งคู่กด พร้อม → A เริ่ม
4. ตรวจ: A ยืนยันไพ่แล้ว B เห็นแค่ "✋ เลือกแล้ว" ไม่เห็นว่าเลือกอะไร (ดู Network tab: ไม่มีข้อมูลไพ่ของ A ใน response/realtime ของ B) · ทั้งคู่ยืนยันแล้วไพ่เปิดพร้อมกัน
5. เล่นจนเกิดสงคราม ลอง "ถอย" และ "ลุย" · ปิดแอป B ค้างไว้ 2 นาที → ต้องแพ้ด้วย "หลุดการเชื่อมต่อ" · ปล่อยเงียบ 60 วินาที → แพ้ "หมดเวลา"
6. จบเกมแล้ว Rematch · ลองเข้าห้อง war คนที่ 3 → ต้องเต็ม
