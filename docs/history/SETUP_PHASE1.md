# Phase 1 — ติดตั้งระบบห้อง/ล็อบบี้ (ทำตามลำดับ)

## A. ฝั่ง Supabase (ครั้งเดียว)

1. เข้า Dashboard ของโปรเจกต์ → **SQL Editor** → **New query**
2. เปิดไฟล์ `supabase/migrations/001_phase1_rooms.sql` คัดลอกทั้งไฟล์ไปวาง → กด **Run**
   ผลที่ถูกต้อง: ขึ้น `Success. No rows returned` (ถ้ามี error ให้แคปหน้าจอส่งมา)
3. เปิดให้ผู้เล่นเข้าแบบไม่ต้องสมัคร: **Authentication → Sign In / Providers** (ชื่อเมนูอาจต่างเล็กน้อยตามเวอร์ชัน)
   → เปิด **Allow anonymous sign-ins** → Save
4. ตรวจว่า Realtime เห็นตาราง: **Database → Publications** → `supabase_realtime` ต้องมี `rooms` และ `room_players`
   (SQL ข้อ 2 เพิ่มให้แล้ว แค่ตรวจซ้ำ)
5. ข้อควรระวัง: ระบบ Auth ของ Supabase มี **ขีดจำกัดจำนวนการ sign-in แบบ anonymous ต่อชั่วโมงต่อ IP** (ค่าเริ่มต้นราว 30 — ตัวเลขนี้ผมยังไม่ได้ตรวจกับเอกสารปัจจุบัน)
   ถ้าทั้งทีมใช้ Wi-Fi เดียวกันตอน offsite อาจชนเพดาน ดูที่ **Authentication → Rate Limits** และปรับได้ถ้าจำเป็น

> ห้ามนำ `service_role` key หรือรหัสผ่านฐานข้อมูลไปใส่ในไฟล์ใด ๆ ของ repo — Phase 1 ไม่ต้องใช้เลย

## C. ทดสอบด้วยเครื่องจริง (เกณฑ์ผ่าน Phase 1)

1. เครื่อง A: แท็บเกม → เกมเลขเพดาน → ปุ่ม **🌐 เล่นออนไลน์** → สร้างห้อง → ได้รหัส 6 ตัว
2. เครื่อง B, C, D: เข้าร่วมห้องด้วยรหัส (หรือกด “ชวนเพื่อน” แล้วเปิดลิงก์)
3. ตรวจ: เห็นชื่อ/รูป/👑 Host/จุดสถานะออนไลน์ ครบทุกเครื่อง และอัปเดตทันที
4. ตรวจ: คนที่ 5 เข้าไม่ได้ (ห้องเต็ม) · รหัสผิดขึ้นข้อความ · ชื่อซ้ำ/รูปซ้ำในห้องถูกปฏิเสธ
5. ตรวจ: ปุ่ม **เริ่มเกม** ใช้ไม่ได้จนกว่าทุกคน (รวม Host) กด พร้อม · มีคนยกเลิก พร้อม → ปุ่มกลับมาใช้ไม่ได้ · Host เปลี่ยนเพดาน/โหมด → ทุกคนต้องกด พร้อม ใหม่
6. ตรวจ: ออกจากห้อง / Host ออก (Host ย้ายให้คนที่เข้าก่อน) / Host ปิดห้อง
7. ตรวจ: ปิดแท็บแล้วเปิดใหม่ → ปุ่มออนไลน์พากลับเข้าห้องเดิม (ผ่าน Anonymous Auth)
8. กด **เริ่มเกม** → ขึ้นหน้า “เริ่มเกมแล้ว” (ส่วนเล่นไพ่จริงคือ Phase 2)
